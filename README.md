# 拠点戦・税収管理ボード（Cloudflare版）

黒い砂漠モバイル 鯖統合の拠点戦・攻城戦を記録して、
**どの拠点の税収が高いか（空席期間が長いか）** と **いまどこを誰が保有しているか** を
ギルド内でURLを共有して見られるようにするWebアプリ。

Cloudflare Workers + D1 で動くので、デプロイすれば
`https://kyoten-tax-board.<あなたのサブドメイン>.workers.dev` で誰でも開ける。

運用開始は **2026-08-17**。それ以前の過去データは引き継がない。

---

## 公開までの手順

```bash
# 1. 依存を入れる
npm install

# 2. Cloudflareにログイン（ブラウザが開く）
npx wrangler login

# 3. D1データベースを作る
npx wrangler d1 create kyoten
#    → 出力された database_id を wrangler.toml の該当行に貼り替える

# 4. テーブルとマスタ（拠点37件・ギルド101件）を投入
npx wrangler d1 migrations apply kyoten --remote

# 5. 編集用パスワードを設定（これを知っている人だけが書き込める）
npx wrangler secret put EDIT_PASSWORD

# 6. 公開
npx wrangler deploy
```

デプロイ後に表示されるURLをギルドに共有する。

### GitHub連携（Workers Builds）で自動デプロイする場合

Cloudflareのダッシュボードからリポジトリをつないでデプロイするときは、次の3つを満たしていること。

1. **`package-lock.json` をリポジトリにコミットする**
   これが無いとCloudflare側の「Installing」が丸ごとスキップされ、`hono` などの依存が入らないまま
   `wrangler deploy` が走って失敗する。
2. **Deploy command は `npx wrangler deploy`**（Build command は空でよい）
3. **`wrangler.toml` の `database_id` を実際の値に置き換えてからpushする**
   プレースホルダのままだとD1が見つからず失敗する

## うまくデプロイできないとき

| ログに出るもの | 原因と対処 |
|---|---|
| `Could not resolve "hono"` / `Could not resolve "fflate"` | `package-lock.json` が無い。コミットしてpushし直す |
| `No dependencies detected to cache. Skipping.` + Installing が一瞬で終わる | 同上。依存がインストールされていない |
| `Couldn't find DB` / `D1 database not found` | `wrangler.toml` の `database_id` がプレースホルダのまま。`npx wrangler d1 create kyoten` の出力を貼る |
| `no such table: nodes` （デプロイは成功するが画面がエラー） | マイグレーション未適用。`npx wrangler d1 migrations apply kyoten --remote` |
| `Authentication error` | `npx wrangler login`、またはビルドトークンの権限に Workers Scripts / D1 の編集権があるか確認 |

手元から直接デプロイする方が早いことも多い。

```bash
npx wrangler deploy
```

## 誰が編集できるか

- **URLを知っている人は誰でも閲覧できる**（税収ランキング・保有状況・履歴）
- **編集できるのは `EDIT_PASSWORD` を入れてログインした人だけ**
  右上の「閲覧のみ（ログイン）」から入る。ログイン状態は90日保持される
- `EDIT_PASSWORD` を設定しないと**誰でも編集できてしまう**ので、公開するなら必ず設定する

## 画面

| タブ | 内容 |
|---|---|
| 週次ボード | 月・木・金・土（攻城戦）・日を縦に並べた入力＋確認画面。右側に税収ランキングと保有サマリ |
| 拠点マスタ | 拠点の等級・開催曜日・枠・時刻などを編集。並び順は 曜日（月木金日土）→ 等級（3→2→1） |
| ギルド管理 | ギルドの追加・改名・有効/無効。**週次ボードのプルダウン候補はここから来る**。<br>手元の `guild_master.csv` を編集したときは、ここに中身を貼り付けて「取り込む」を押すと、名前が一致するギルドはメモを上書き、新しい名前は追加される（プルダウンとExcelの両方に反映） |
| 履歴 | 拠点ごとの占領・放棄の記録と、税がどう算出されたか |

週次ボードの列は左から
**拠点 → 級 → 時 → 塞 → 枠 → 人数 → いま保有しているギルド → 保有日数 → 税（空席日数）→ ［入力欄］**。
入力する前に「いま誰が持っていて、どれだけ美味しいか」が見えるようにしてある。
黄色いセルが入力欄、白いセルは自動計算とマスタ表示。

## 週の使い方

1. **月曜 朝10時まで** — 月・木・金・日の4日分の「統一」「宴会」にチェックを入れる
2. **当日 朝10時（19時開催）／12時（21時開催）** — 「対戦ギルド」を選ぶ。
   候補は入札権のあるギルドだけに自動で絞り込まれる
3. **結果が出次第** — 「勝ったギルド」を、2で選んだ対戦ギルドの中から選ぶ

「保存」でD1に保存される。週の切り替えは「◀ 前の週 / 次の週 ▶」。

## Excel

ツールバーの **「全データをExcelでダウンロード」** で、
その時点の**すべてのデータが入った1つの .xlsx** が落ちてくる。

| シート | 内容 |
|---|---|
| 今週の記録 | 現在の週の拠点戦・攻城戦を1戦1行で（週次ボードと同じ項目）。税・保有日数あり。曜日ごとに行の色を変えてある |
| 過去の記録 | 今週より前の記録（週ごとに緑の区切り）。**税・保有日数の列は含まない**（今週分と別に保存） |
| 税収ランキング | 空席日数が長い順。常に最新の状態で計算 |
| 保有状況 | 等級ごとの保有/空席と、拠点ごとの現保有ギルド。常に最新の状態で計算 |
| 拠点マスタ / ギルド一覧 | マスタの写し |

データ本体はD1にあるので、Excelはいつダウンロードしても常に最新。
週ごとにファイルが分かれることはない。

> ギルド名に `Bagaиі` `βυsнỉȉdo家族` `RaиkSS` のような文字が混ざっているのは文字化けではなく、
> 現行スプレッドシートの表記そのまま（101件すべて一致を確認済み）。
> CSVで開くと化けることがあるので、確認はこのExcelかアプリ画面で行う。

## 計算ルール

| 用語 | 意味 |
|---|---|
| 獲得日 | そのギルドがその拠点を取った日 |
| 放棄日 | 次のうち早い方 ①その拠点で次に決着がついた日 ②そのギルドが他の拠点で勝った日（＝移動して手放した） |
| 保有日数 | 放棄日（未放棄なら今日） − 獲得日 |
| **税（空席日数）** | **前回の放棄日 → 今回の獲得日 までの日数** |

税は「その拠点が空いていた期間」。長いほど、入札して勝ったときに得られる利益が大きい。
ギルドが長く保有していることが良いという意味ではない。

攻城戦（カルフェオン／バレンシア）の勝利も「移動」として扱うので、
城を取ったギルドはそれまで持っていた拠点を手放す。

### 入札権

等級は **城 ＞ 3 ＞ 2 ＞ 1**。

- 保有している等級と同じか、それより上の等級にのみ入札できる
- 下位の等級へは入札できない
- 拠点を持っていないギルドは 1〜3 に入札できる（攻城戦は不可）
- 攻城戦は 2 か 3（または城）を保有しているギルドのみ
- 勝つと元の拠点を手放して移動する。負けても元の拠点は保持する

## 運用開始時の初期登録

過去データを引き継がないので、初回サイクルの税は起点がなく空欄（`—`）になる。
開始時点の保有ギルドと、税の起点になる前回放棄日を入れておくと1週目から税が出る。

```bash
curl -X POST https://<あなたのURL>/api/initial-holding \
  -H "Content-Type: application/json" \
  -H "Cookie: kyoten_edit=<ログイン後のCookie>" \
  -d '{"node_id":5,"guild_id":12,"acquired_date":"2026-08-09","last_released_date":"2026-08-02"}'
```

もしくは D1 に直接:

```bash
npx wrangler d1 execute kyoten --remote --command \
  "INSERT INTO initial_holdings (node_id, guild_id, acquired_date, last_released_date)
   VALUES (5, 12, '2026-08-09', '2026-08-02')"
```

## 拠点配置が変わったとき

拠点の等級・開催曜日・枠は**今後変わる前提**なので、税収の計算ロジックとは切り離してある。
「拠点マスタ」タブを書き換えるだけで週次ボードの並びが変わり、`src/calc.ts` には手を入れなくてよい。
`適用開始日` を持たせているので、過去の記録は壊れない。
