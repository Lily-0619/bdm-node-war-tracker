# 05. 人間確認が必要な曖昧点

Claude側で勝手に意味を確定しない項目。

## 1. `x` の業務上の正式な意味

挙動は判明しているが、「未占領」「該当なし」「特殊処理」など正式名称は未確定。

## 2. `対戦` の数字の正式な意味

入力値は0〜6程度。現行表示では最大枠と組み合わせて ●○ 表示に使われる。変数名は一旦 `battle_count` としているが、正式に「参加ギルド数」「入札数」等のどれかは確認したい。

## 3. `計算用` の旧 `人数` 補助列

DBには人数という列名があるが、実表示の人数は拠点マスタのcapacityから取る。旧補助列が現在必要か確認する。

## 4. 時間コード 19 / 21

現行表示には「22時」判定があり、内部コードとの名称が直感的に一致しない。Web版ではまず `legacy_time_code` のまま移行し、表示時刻は確認後に確定する。

## 5. 曜日不一致（8拠点）

`計算用` と `入力` 上の配置が一致しない。

- アト農場: 計算用 `水` / 入力UI `月`（3B）
- 略奪の森: 計算用 `水` / 入力UI `日`（2A）
- 高原地帯: 計算用 `日` / 入力UI `月`（2C）
- マルニの第2実験場: 計算用 `水` / 入力UI `木`（2C）
- 旧ダンデリオン: 計算用 `水` / 入力UI `日`（1B）
- カイア渡し場: 計算用 `水` / 入力UI `月`（1D）
- エントの森: 計算用 `水` / 入力UI `木`（1D）
- 廃鉄鉱山採掘場: 計算用 `水` / 入力UI `金`（1E）

現行運用の正解がどちらなのか確認し、`node_schedule` のeffective date付きで確定するのが安全。

## 6. 税の単位/表示

計算値は実質「日数」。UI上でどのように税額・星・段階へ変換するかは別仕様として確認する。

## 7. 攻城戦の攻城1/攻城2

旧放棄判定では勝者だけが次回獲得扱いに入る。攻城1/2を将来別用途に使うか確認する。
