## ユーザーの考えている作業

難しい全面再設計ではなく、基本的には次の3点。

1. ギルドカルテの必要な機能を税収システムへ付ける
2. 整理できていない部分を、移管しながら整理する
3. 必要な追加機能を付ける

このシンプルな認識を基準に進める。ユーザーへの説明も、専門用語を増やさず簡潔に行う。

## 最大の目標

`bdm-guild-karte-v2`にはギルド・個人情報の収集、集計、Excel、SQLite、カルテ画像生成、ローカル画面、Discord Botが混在している。

Discord Bot機能を中心に元リポジトリへ残し、それ以外のギルド・個人データの収集、管理、編集、閲覧機能を税収システムへ移管する。

データがExcel、SQLite、ローカルフォルダなどに点在している状態を解消し、サイトから閲覧・管理できるようにする。

## 実現したい機能

- 見たいギルドを選択する
- ギルドに関する情報を見やすく、おしゃれにまとめて表示する
- 所属メンバー個人のデータも表示する
- Main CPだけでなくFCPと職も記録する
- 個人ごとに、使用職と期間ごとのCP/FCP増加量を確認できるようにする
- ギルド単位のデータ収集を週1回の定刻に自動実行する
- 個人データ統合の難しい修正は、必要ならオフライン作業でもよい
- 現在Excelで管理している個人データは、必要がなければDB管理へ移す
- DBの内容をWebから検索・閲覧できるようにする
- DBonk由来のデータを表示する「風車マーク」の機能は、パスワードなしでは閲覧できないようにする

## 合意している基本方針

- `bdm-node-war-tracker`をWeb・D1・集計・収集の中心にする
- `bdm-guild-karte-v2`はDiscord Bot中心へ整理する
- Excelは正本にせず、初回移行、バックアップ、出力用途にする
- CP、FCP、職は最新値だけを上書きせず、取得日ごとの履歴として保存する
- 既存の税収機能を壊さず、段階的に追加する
- DBonk本体のログイン情報と、サイトの閲覧パスワードは別にする
- 風車機能はリンクを隠すだけでなく、画面、API、Excel出力をサーバー側で保護する

## 当初の工程

1. ギルドカルテの内容を理解する。風車マーク／DBonk由来データの認証範囲を決める
2. Excel管理部分を含め、現在集積しているデータを一覧化し、ユーザーと相談する
3. ギルドカルテの移管計画を立てる
4. 追加機能を盛り込む

## 確認済みの運用ルール

- 解析機能だけを税収リポジトリへ移し、Discord Botは元リポジトリへ残す
- 収集対象は登録リストにある全ギルド（現在29ギルド）
- HPのボタン1回で全ギルドをバックグラウンド収集する
- 初期は手動実行。週次自動実行は動作確認後に追加する
- 最初の追跡対象者は0人。管理者が追跡対象を選ぶ
- 家門名変更は自動統合せず、管理者が判断する
- Name Searchは選択した追跡対象者だけに使う
- サイトの既存編集パスワードで画面と管理APIを保護する
- 過去SQLite/Excelの履歴をD1へ移し、その後の収集データもD1へ蓄積し続ける

## 再開時の注意

- ユーザーは、小難しいシステム説明より、結論を短く知りたい
- 勝手に大規模な作り直しへ話を広げない
- 相談が必要な項目は一つずつ確認する
- 実装開始前に、画像とExcelを確認する
- GitHub上で完結する作業を前提とし、ユーザーのPCが起動していることを前提にしない
